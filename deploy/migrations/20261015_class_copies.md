# 逐班份数与封面升级

升级前停止云端服务，确认无未完成上传，核对当前连接的是 `PRINT_CLOUD_DB_URL` 指向的 PostgreSQL，还是 `PRINT_DATA_DIR/cloud.db`（未设置时为项目 `data/cloud.db`）中的 SQLite。先在备份副本上演练，再对生产库执行。同目录的 SQL 一次只运行一种；旧任务三列应分别默认为 `[]`、`[]`、`0`。桌面本地库无需迁移。

- SQLite：停服务后用 `sqlite3 <实际 cloud.db 路径> ".backup '<备份文件路径>'"` 做一致性备份；用 `sqlite3 <备份文件路径> "PRAGMA integrity_check;"` 确认结果为 `ok`。演练完成后，对生产库执行 `sqlite3 <实际 cloud.db 路径> < 20261015_class_copies_sqlite.sql`。核对 `PRAGMA table_info(school_presets);` 与 `PRAGMA table_info(tasks);` 的新列，且旧行默认值正确。
- PostgreSQL：停服务后用 `pg_dump -Fc -f <备份文件路径> <实际数据库连接参数>` 备份，用 `pg_restore -l <备份文件路径>` 核对备份目录，再向隔离的测试库恢复并演练。生产库执行 `psql -v ON_ERROR_STOP=1 <实际数据库连接参数> -f 20261015_class_copies_postgres.sql`，核对两张表的新列和旧行默认值。连接参数只在现场传入，不写入仓库或日志。

数据库 `init` 会检查字段，不会自动迁移；缺少字段时新服务拒绝启动。先更新云端，再更新所有要打印新任务的桌面客户端。旧桌面客户端领取含封面或特殊班级份数的任务时，云端会拒绝并提示升级；已有的统一份数、无封面任务仍可打印。若旧客户端曾为新任务生成过未开始打印的本地缓存，新客户端会在领取时重新生成；已开始打印的缓存不会自动替换。

回退时先停服务和打印，备份升级后的库，再恢复升级前的备份：SQLite 用备份文件替换原 `cloud.db`，PostgreSQL 将 `pg_dump` 的备份恢复到原库并核对任务、学校记录。若已产生使用新字段的任务，恢复旧库会丢失备份之后的新任务，须先保留并处理这些任务。旧应用无法识别新任务的逐班设置，不得只回退应用而继续处理新任务。
