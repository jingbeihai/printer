## 工作流程

小改直接在执行聊天讨论、修改和验证；普通功能只确认关键行为后实施；高风险改动先明确方案。按任务组织执行聊天，同一目标可跨模块实施；在同一聊天先用 Plan 讨论，再切换模式修改，不必每次经过总控或新开聊天。总控负责方向、优先级和按需汇总进度。

任务状态：待讨论 → 已确认 → 开发中 → 待验收 → 已完成。阻塞时说明具体原因；未完成的真机验证单独标注。

日常修改只简要汇报，不自动正式记账。用户主动说“收尾”时，汇总多轮修改并更新 doc/CHANGELOG.md（首次使用时创建）、已有任务文档和任务总表；架构变化才更新 PROJECT.md。重复收尾补充原记录，未完成或未验收的任务保留真实状态。小改不强制新建任务文档。用户说“交接”时整理进度、决定和待办，供新聊天继续，无需通读原聊天。Plan 模式只输出内容，切换模式后才能写入。具体口令规则见 AGENTS.md。

当前架构描述已实现的事实；任务文档描述计划与结果；历史文件明确标注归档。不要把未实施的想法直接写成架构事实。AGENTS.md 是指令入口，保留在规则发现位置，是文档集中存放的例外。
